## When to use

- To display a collection of structured data.
- To sort, search, paginate, filter, select or expand that data.

The API mirrors antd `Table` (columns, `dataSource`, `rowKey`, `pagination`, `rowSelection`, `expandable`, …) and the rendering engine is `@rc-component/table`, the one antd uses. Popups and controls (filter panel, selection menu, pager, tooltips, checkboxes) are lobe base-ui components; no antd component is used. The demos below follow the order of antd's docs, so each antd demo has a counterpart here; the only omission is listed under [Differences from antd Table](#differences-from-antd-table-migration).

```tsx
import { Table } from '@lobehub/ui/base-ui';

const dataSource = [
  { key: '1', name: 'Mike', age: 32, address: '10 Downing Street' },
  { key: '2', name: 'John', age: 42, address: '10 Downing Street' },
];

const columns = [
  { title: 'Name', dataIndex: 'name', key: 'name' },
  { title: 'Age', dataIndex: 'age', key: 'age' },
  { title: 'Address', dataIndex: 'address', key: 'address' },
];

<Table dataSource={dataSource} columns={columns} />;
```

## Row selection

`rowSelection` adds a selection column of checkboxes (or radios with `type: 'radio'`). `getCheckboxProps` returns per-row props such as `disabled` and `name`. `onChange(selectedRowKeys, selectedRows, { type })` reports every change, with `type` one of `single`, `multiple` (Shift-click range), `all`, `invert` or `none`; `onSelect(record, selected, selectedRows, nativeEvent)` reports single clicks.

## Custom selection

`selections` adds a dropdown beside the select-all checkbox. `true` gives the presets: `Table.SELECTION_ALL` (every row of every page), `Table.SELECTION_INVERT` (the current page) and `Table.SELECTION_NONE`; custom `{ key, text, onSelect }` items receive the selectable keys of the current page. ## Filter and sorter

`filters` + `onFilter` filter locally: tick options in the panel and press OK (closing the panel also applies, unless `filterOnClose: false`). `filters.children` nest options in a group, and `filterSearch` adds a search box. `sorter` takes a compare function, `defaultSortOrder` sets the initial order and `sortDirections` limits the cycle (Name only sorts descending). `showSorterTooltip={{ target: 'sorter-icon' }}` moves the hint tooltip from the whole header to the sort icon.

## Multiple sorter

`sorter: { compare, multiple }` joins a multi-column sort; a higher `multiple` sorts first. With more than one active sorter, `onChange` receives an array of `{ column, columnKey, field, order }`.

## Reset filters and sorters

`filteredValue` and `sortOrder` make filters and sorting controlled: keep what `onChange` reports in state and pass it back, then clear it from outside the table. Use `null` (not `undefined`) for an empty controlled value. `defaultFilteredValue` sets an uncontrolled initial filter, and `filterResetToDefaultFilteredValue` makes Reset return to it.

## Customized filter panel

`filterDropdown` replaces the panel. As a function it receives `selectedKeys` / `setSelectedKeys` (the draft), `confirm({ closeDropdown })`, `clearFilters({ confirm, closeDropdown })`, `close`, `filters` and `visible`. `filterIcon` receives whether the column is filtered, `filtered` forces that state, and `filterDropdownProps` takes the popup options (`open` / `onOpenChange`, `placement`, `getPopupContainer`, `popupRender`); `filterDropdownOpen` / `onFilterDropdownOpenChange` are kept as deprecated aliases.

<Demo of={DemoCustomFilterPanel} />

## Ajax

`sorter: true` and filters without `onFilter` leave the rows alone and report through `onChange`; `pagination.total` switches the pager to server mode. Fetch the page yourself (here from a mock endpoint) and pass it as `dataSource`, with `loading` while it loads. Here pagination (`current` / `pageSize`), `sortOrder` and `filteredValue` are all controlled by one query object, updated from `onChange`; its fourth argument `extra.action` tells whether the change came from `paginate`, `sort` or `filter`. Like antd, filtering returns to page 1 while sorting keeps the page, and `scroll` scrolls back to the first row on every change.

## colSpan and rowSpan

Header cells merge with `column.colSpan` (`0` hides a cell). Body cells merge when `onCell` (or a `render` returning `{ children, props }`) sets `colSpan` / `rowSpan`; a span of `0` skips the cell. `rowScope: 'row'` renders the first column as row headers.

<Demo of={DemoColspanRowspan} />

## Tree data

Records with a `children` array render as a collapsible tree; `expandable.childrenColumnName` reads another field and `indentSize` (default 15px) sets the indent per level. Sorting and filtering apply at every level, pagination counts top-level records, and `rowClassName` receives the depth as its third argument. With `rowSelection`, the tree toggle moves to the column after the checkboxes; `checkStrictly: false` links parents and children (checking a parent checks its descendants, and a parent shows half-checked while only some are).

### Table

| Property | Description | Type | Default |
| --- | --- | --- | --- |
| bordered | Show all cell borders | `boolean` | `false` |
| children | `Table.Column` / `Table.ColumnGroup` elements, used when `columns` is not set | `ReactNode` | - |
| classNames | Class per semantic part; object or function of `{ props }`. See [Semantic DOM](#semantic-dom) | `TableClassNames \| (info: { props }) => TableClassNames` | - |
| column | Props merged under every column and group (a column's own fields win) | `Partial<TableColumnType>` | - |
| columns | Columns of the table | [`TableColumnsType`](#column) | - |
| components | Override the `table`, `header.{wrapper,row,cell}` and `body.{wrapper,row,cell}` elements (rc-table `TableComponents`) | `TableComponents` | - |
| dataSource | Records to display | `T[]` | `[]` |
| emptyText | lobe alias of `locale.emptyText` (which wins) | `ReactNode \| () => ReactNode` | - |
| expandable | Expandable rows and tree data, see [expandable](#expandable) | `TableExpandableConfig` | - |
| footer | Footer renderer | `(currentPageData) => ReactNode` | - |
| getPopupContainer | Container of the filter popups | `(triggerNode) => HTMLElement` | base-ui portal root |
| loading | Loading overlay | `boolean \| SpinProps` (base-ui `Spin`) | `false` |
| locale | Texts of the table, see [locale](#locale) | `TableLocale` | `@lobehub/ui/i18n` `table.*` |
| measureRowRender | Wrap the hidden row rc-table uses to measure column widths | `(measureRow) => ReactNode` | - |
| pagination | Pager config, see [pagination](#pagination); `false` hides it | `false \| TablePaginationConfig` | - |
| rootClassName | Extra class on the root element | `string` | - |
| rowClassName | Row class; a function also receives the tree depth | `string \| (record, index, indent) => string` | - |
| rowHoverable | Highlight the hovered row | `boolean` | `true` |
| rowKey | Row key: a field name or a function | `string \| (record, index?) => Key` | `'key'` |
| rowSelection | Row selection, see [rowSelection](#rowselection) | `TableRowSelection` | - |
| scroll | Scroll area, see [scroll](#scroll) | `{ x?, y?, scrollToFirstRowOnChange? }` | - |
| showHeader | Show the header | `boolean` | `true` |
| showSorterTooltip | Tooltip on sortable headers telling what the next click does; an object goes to the base-ui `Tooltip` | `boolean \| TooltipProps & { target?: 'full-header' \| 'sorter-icon' }` | `{ target: 'full-header' }` |
| size | Size of the table (`middle` is an alias of `medium`) | `'large' \| 'medium' \| 'small'` | `'medium'` |
| sortDirections | Default `sortDirections` of every column | `SortOrder[]` | `['ascend', 'descend']` |
| sticky | Stick the header and horizontal scrollbar to the page | `boolean \| { offsetHeader?, offsetSummary?, offsetScroll?, getContainer? }` | - |
| styles | Style per semantic part; object or function of `{ props }` | `TableStyles \| (info: { props }) => TableStyles` | - |
| summary | Summary rows built from `Table.Summary` | `(currentPageData) => ReactNode` | - |
| tableLayout | CSS `table-layout` | `'auto' \| 'fixed'` | `fixed` with fixed columns, `scroll.y` or `ellipsis`; otherwise `auto` |
| title | Title renderer | `(currentPageData) => ReactNode` | - |
| virtual | Virtual scrolling; needs a numeric `scroll.y` | `boolean` | - |
| onChange | Pagination, filters or sorter changed | `(pagination, filters, sorter \| sorter[], extra: { currentDataSource, action: 'paginate' \| 'sort' \| 'filter' }) => void` | - |
| onHeaderRow | Props of each header row | `(columns, index) => HTMLAttributes` | - |
| onRow | Props of each body row | `(record, index) => HTMLAttributes` | - |
| onScroll | Body scrolled (only vertical scrolling with `virtual`) | `(event) => void` | - |

Deprecated top-level props kept from antd: `expandedRowRender`, `expandIcon`, `expandIconColumnIndex`, `indentSize` and `childrenColumnName` (use `expandable.*`).

`onRow`, `onHeaderRow`, `onCell` and `onHeaderCell` all return element props:

```tsx
<Table
  onRow={(record, rowIndex) => ({
    onClick: (event) => {}, // click row
    onDoubleClick: (event) => {}, // double click row
    onContextMenu: (event) => {}, // right click row
    onMouseEnter: (event) => {}, // mouse enter row
    onMouseLeave: (event) => {}, // mouse leave row
  })}
  onHeaderRow={(columns, index) => ({
    onClick: () => {}, // click header row
  })}
/>
```

### Table ref

The ref is the root `div`, extended with antd's members.

| Property | Description | Type |
| --- | --- | --- |
| nativeElement | The root element | `HTMLDivElement` |
| scrollTo | Scroll the body: `index` / `key` (matched against `rowKey`) bring a row into view, `align` places it (`'start' \| 'end' \| 'nearest'`) and `offset` adds pixels; `top` scrolls to a pixel offset. Works with `virtual` | `(config: { index?, key?, top?, offset?, align? }) => void` |

### Static members

| Member | Description |
| --- | --- |
| `Table.Column` | JSX column, takes the [Column](#column) props |
| `Table.ColumnGroup` | JSX column group, takes `title` plus `Table.Column` children |
| `Table.Summary` / `Table.Summary.Row` / `Table.Summary.Cell` | Summary rows, see [Table.Summary](#table-summary) |
| `Table.EXPAND_COLUMN` | Placeholder in `columns` for the expand column |
| `Table.SELECTION_COLUMN` | Placeholder in `columns` for the selection column |
| `Table.SELECTION_ALL` / `Table.SELECTION_INVERT` / `Table.SELECTION_NONE` | Preset `rowSelection.selections` items |

### Column

One entry of `columns`; `Table.Column` takes the same props.

| Property | Description | Type | Default |
| --- | --- | --- | --- |
| align | Alignment (`start` / `end` follow the writing direction) | `'left' \| 'right' \| 'center' \| 'start' \| 'end'` | `'left'` |
| className | Class of the column's cells | `string` | - |
| colSpan | Header span; `0` hides the header cell | `number` | - |
| dataIndex | Field of the record, or a path such as `['address', 'city']` | `string \| string[]` | - |
| defaultFilteredValue | Initial filter (uncontrolled) | `FilterValue[] \| null` | - |
| defaultSortOrder | Initial sort order | `'ascend' \| 'descend' \| null` | - |
| ellipsis | Truncate cells and header; switches `tableLayout` to `fixed`. `showTitle: false` drops the native tooltip | `boolean \| { showTitle?: boolean }` | `false` |
| filterDropdown | Custom filter panel | `ReactNode \| (props: FilterDropdownProps) => ReactNode` | - |
| filterDropdownProps | Popup options: `open` / `onOpenChange`, `placement`, `getPopupContainer`, `popupRender`, `className`, `rootClassName`, `style`, `zIndex` | `TableFilterDropdownPopupProps` | - |
| filtered | Force the filter icon's active state | `boolean` | `false` |
| filteredValue | Controlled filter (`null` for none) | `FilterValue[] \| null` | - |
| filterIcon | Custom filter icon | `ReactNode \| (filtered: boolean) => ReactNode` | - |
| filterMode | Filter panel layout | `'menu' \| 'tree'` | `'menu'` |
| filterMultiple | Multiple values (checkboxes) or one (radios) | `boolean` | `true` |
| filterOnClose | Apply the draft when the panel closes without OK | `boolean` | `true` |
| filterResetToDefaultFilteredValue | Reset returns to `defaultFilteredValue` | `boolean` | `false` |

## Semantic DOM

`classNames` and `styles` follow antd 6's Semantic DOM. Each takes an object, or a function `({ props }) => object` computed from the table's props.

| Key | Element |
| --- | --- |
| `root` | Root `div` (`.lobe-table-wrapper`); `rootClassName` and `className` land here too |
| `section` | Table container (`.lobe-table-container`) |
| `title` / `footer` | Title and footer bars (`title()` / `footer()`) |
| `content` | Scroll box around the `table` (`.lobe-table-content`, without a fixed header) |
| `header.wrapper` / `header.row` / `header.cell` | `thead` / its `tr` / `th` |
| `body.wrapper` / `body.row` / `body.cell` | `tbody` / its `tr` / `td` |
| `pagination.root` / `pagination.item` | Pager `nav` / its page-number buttons; merged with `pagination.classNames` / `pagination.styles` |

The flat keys from before still work: `wrapper` → `section`, `header` (a string, or a style object without `wrapper` / `row` / `cell`) → `header.cell`, `body` (likewise) → `body.wrapper`, `row` → `body.row` and `cell` → `body.cell`.

## Design Token

The table has no component tokens. It reads the global antd-style theme tokens of `ThemeProvider` (colors, radius, motion); restyle it per instance with `classNames` / `styles`. See [Differences from antd Table](#differences-from-antd-table-migration).

## Differences from antd Table / migration

Swap the import from `antd` to `@lobehub/ui/base-ui`; `columns`, `dataSource`, `rowKey` (defaults to `'key'`), `pagination`, `rowSelection`, `expandable`, `scroll`, `sticky`, `summary`, `virtual`, `components`, `locale`, `classNames` / `styles`, the `onChange` arguments, the ref and the static members keep antd's shape (see [API](#api)). What differs:

**Not supported on purpose (no equivalent API)**

| antd | Why | Use instead |
| --- | --- | --- |
| `prefixCls` / `dropdownPrefixCls` | antd's CSS class-prefix system; this library styles with antd-style and fixed `lobe-table-*` classes. `FilterDropdownProps.prefixCls` and `expandIcon`'s `prefixCls` receive a fixed value | `className` / `rootClassName`, `classNames` / `styles` (Semantic DOM), `filterDropdownProps.className` |
| `ConfigProvider` global `table` config (`classNames`, `styles`, `rowKey`, `scroll`, `expandable.expandIcon`) | base-ui components do not read antd's `ConfigProvider` | Set the props per table, or wrap `Table` in your own component with the defaults; the table-level `column` prop covers shared column props |
| `ConfigProvider.renderEmpty` | Same reason | `locale.emptyText` (node or function), or the lobe `emptyText` alias |
| Component Design Token (`theme.components.Table`, the `component-token` debug demo) | No per-component token layer; the table reads the global `ThemeProvider` tokens | `ThemeProvider` theme for global colors / radius, `classNames` / `styles` for per-table overrides (see the semantic styling demo) |

**Behaviour and API differences**

- `size` defaults to `medium` (antd: `large`); `middle` is accepted as an alias of `medium`.
- `locale` defaults come from `@lobehub/ui/i18n` (`ConfigProvider` with `resources`), not antd's locale packages.
- Controls are base-ui components: `loading` takes base-ui `Spin` props, `showSorterTooltip` base-ui `Tooltip` props, `rowSelection.getCheckboxProps` base-ui `Checkbox` props, and `filterDropdownProps` the subset of `DropdownProps` listed under [Column](#column). `getCheckboxProps().onChange` receives the new checked state (the base-ui `Checkbox` signature) instead of an event.
- The default expand toggle is a lobe button (`aria-label` "Expand row" / "Collapse row"); selected rows get the `lobe-table-row-selected` class. Replace `.ant-table-*` style overrides with `classNames` / `styles`.
- `emptyText` is an extra (lobe-only) alias of `locale.emptyText`.
- Column resizing is not built in (antd has none either).
- The editable demos keep their draft in React state instead of antd `Form`, and confirm with a base-ui `Popover` instead of `Popconfirm`; the pattern (`components.body.cell` + `onCell`) is the same.
