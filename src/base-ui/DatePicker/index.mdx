## Basic

`picker` switches between `date`, `week`, `month`, `quarter` and `year`; each has antd's default format (`YYYY-MM-DD`, `gggg-wo`, `YYYY-MM`, `YYYY-[Q]Q`, `YYYY`) and placeholder. The year panel shows a decade (10 years plus the neighbours at either end), and its header drills up to a century of decades. `onChange` receives `(date: Dayjs | null, dateString: string | null)`; clearing passes `null` for both. The input is typeable — a date in `format` is parsed as you type and committed on Enter or blur.

## Range

`DateRangePicker` takes and emits a `[Dayjs, Dayjs]` pair (or `null` once cleared), with `dateStrings` as the second argument.

## Range picker types

`picker` works on `DateRangePicker` too: `week`, `month`, `quarter` and `year` show two adjacent panels (two years of months / quarters, two decades of years) and get range placeholders such as "Start month" / "End month". `id={{ start, end }}` sets the ids of the two inputs, and `onFocus` / `onBlur` / `onCalendarChange` receive `info.range` (`'start'` or `'end'`) — focus or pick in the first picker to see it.

<Demo of={DemoRangePicker} layout="bare" />

## Range interaction

Clicking the end input first makes the end active, so the end date is picked first and the start second. Tab moves to the other end (as in antd, an empty end that does not allow empty keeps the focus). `ref.focus(index)` / `ref.focus({ index })` focuses the start (`0`) or end (`1`). `order` (default `true`) swaps a reversed pair; `order={false}` keeps it as entered.

## Date format

`format` takes the same `FormatType` as antd:

- a dayjs format string (`'YYYY/MM/DD'`) — used to show the value, build the `dateString` and parse what is typed;
- a function `(value: Dayjs) => string` — display only; typed text can no longer be parsed;
- an array of strings / functions — the first one is used to show the value and build `dateString`, and typed text is tried against every string format in turn (`13/10/26` and `13-10-2026` both match `['DD/MM/YYYY', 'DD/MM/YY', 'DD-MM-YYYY', 'DD-MM-YY']`). Put a function first and strings after it to show custom text while still accepting typed dates.

Defaults follow antd: `YYYY-MM-DD` (`YYYY-MM-DD HH:mm:ss` with `showTime`), `gggg-wo`, `YYYY-MM`, `YYYY-[Q]Q` and `YYYY` per `picker`.

Typed text is parsed in strict mode through dayjs's `customParseFormat` plugin, which the picker registers itself. To build a `Dayjs` from a string in a custom format in your own code (`dayjs('2015/01/01', 'YYYY/MM/DD')`), extend dayjs with it once, as in antd:

```ts
import dayjs from 'dayjs';
import customParseFormat from 'dayjs/plugin/customParseFormat';

dayjs.extend(customParseFormat);
```

## Mask input

`format={{ format, type: 'mask' }}` turns the input into a masked field, as in antd 5.14+: on focus the empty input shows the format as a template, digits fill one segment at a time and move on, ArrowUp / ArrowDown step the focused segment, ArrowLeft / ArrowRight move between segments, Backspace resets one, and pasting a full date in the format fills it. Enter commits the date. Works on the range picker too.

## Date and time

`showTime` puts the time panel next to the date panel; the default format becomes `YYYY-MM-DD HH:mm:ss`. `picker="time"` (or a controlled `mode="time"`) shows the time panel alone, with the `HH:mm:ss` format and the "Select time" / "Start time" placeholders. `showTime` takes the antd `SharedTimeProps` object:

- `format` decides which columns are shown (`'HH:mm'` drops seconds, `'h:mm a'` adds AM / PM); the input keeps `format`, so set both when they should match;
- `showHour` / `showMinute` / `showSecond` / `showMillisecond` and `use12Hours` set the columns explicitly;
- `hourStep` / `minuteStep` / `secondStep` / `millisecondStep` thin the options;
- `hideDisabledOptions` removes the options `disabledTime` disables instead of greying them;
- `defaultOpenValue` is the time a picked date gets before any time is chosen (`defaultValue` is its deprecated alias; a top-level `defaultOpenValue` works too);
- `changeOnScroll` picks the option a column is scrolled to.

The time props can also be passed at the top level (`use12Hours`, `hourStep`, …), as in antd. With `showTime`, picking only fills the input; `onOk(value)` fires on the OK button, which commits the value. The **Now** button (`showNow`, on by default on single pickers, off on `DateRangePicker`) fills in the current time.

<Demo of={DemoTime} layout="bare" />

## Need confirm

`needConfirm` adds the OK button to any picker, so the value is only committed once confirmed. It defaults to `true` with `showTime` and `picker="time"`; `needConfirm={false}` commits as soon as the popup closes (on blur, Enter or a click outside). The deprecated `changeOnBlur` maps to `needConfirm={false}`. The OK button is a small primary base-ui `Button`; `components.button` replaces it.

<Demo of={DemoNeedConfirm} layout="bare" />

## Disabled date and time

`disabledDate(current, info)` disables cells on every panel; `disabledTime(date)` returns `disabledHours` / `disabledMinutes(hour)` / `disabledSeconds(hour, minute)` / `disabledMilliseconds(…)` for the time columns. On `DateRangePicker` it is `disabledTime(date, partial, info)`, where `partial` is `'start'` or `'end'` and `info.from` is the start already picked — the last example keeps the end from being earlier than the start on the same day.

## Preview value

While you hover a cell, the input shows that value in a muted colour (`previewValue="hover"`, the default); leaving the cell restores it. `previewValue={false}` turns this off. On the range picker the hover only fills the field being picked.

## Customized cell rendering

`cellRender(current, info)` renders every cell of every panel. `info` carries `originNode` (the default cell), `today`, `type` (`date` / `week` / `month` / `quarter` / `year` / `decade` / `time`), `locale`, `prefixCls`, on time cells `subType` (`hour` / `minute` / `second` / `millisecond` / `meridiem`, with `current` being the cell's number) and, on `DateRangePicker`, `range` (`'start'` / `'end'`). The deprecated `dateRender(current, today)` and `monthCellRender(current, locale)` still work for the date and month panels when `cellRender` is not set.

## Preset ranges

`presets` adds a sidebar of quick picks to `DatePicker` (`{ label, value: Dayjs }[]`) and `DateRangePicker` (`{ label, value: [Dayjs, Dayjs] }[]`). `value` may be a function, evaluated when the preset is hovered (the input previews it) or picked, so presets relative to "now" stay current. ## Customized components

`components` swaps in your own panel per mode (`date` / `week` / `month` / `quarter` / `year` / `decade` / `time`), the `input` element or the OK `button` (the default is a small primary base-ui `Button`). A custom panel receives `PickerPanelProps`: `value`, `onHover(date)` previews the date in the input and `onSelect(date)` picks it, closing the popup unless confirmation is needed. ## Buddhist Era

Values stay Gregorian `Dayjs` objects; only the display changes. lobe has no ConfigProvider `locale.DatePicker`, so a locale shared by several pickers goes through a wrapper component.

## Locale

`locale` takes antd's `PickerLocale`: `lang` (texts, placeholders, `field*Format` / `yearFormat` / `cellDateFormat` / `monthBeforeYear`, `shortWeekDays` / `shortMonths`, and `locale`, the rc-picker code picking the dayjs locale) plus `timePickerLocale`. `datePickerLocaleEnUS` and `datePickerLocaleZhCN` are the exported defaults (antd's `date-picker/locale/en_US` / `zh_CN`; they also carry their own `shortWeekDays` / `shortMonths`), and `createPickerLocale(resources, code)` builds one from `datePicker.*` i18n resources. A partial `locale` is merged field by field over the default.

Without `locale`, the texts come from the `@lobehub/ui/i18n` resources of the surrounding `ConfigProvider` and the week / month names from `dayjs.locale()` — load and set the dayjs locale yourself (`import 'dayjs/locale/zh-cn'`), as with antd.

## APIs

<Api name="DatePicker" from=".." />

<Api name="DateRangePicker" from=".." />

Values are `Dayjs` objects, exactly as in antd. `minDate` / `maxDate` replace `min` / `max`, which remain as deprecated aliases; `footer` is a deprecated alias of `renderExtraFooter`, and `onSelect` of `onCalendarChange`. Week start and week / month names follow the active dayjs locale, or `locale.lang.locale` when set (see Locale).

The popup is rendered with `@rc-component/trigger`. Inside a base-ui floating layer (Popover, DropdownMenu) or a dialog it mounts in that layer, so picking a date never counts as an outside click for the host; elsewhere it mounts on `document.body` like antd, carrying the theme's CSS-variable scope so light / dark tokens still apply. It takes its z-index from the shared base-ui layer counter. Pass `getPopupContainer` to mount it elsewhere.

### Keyboard

Input keys match antd DatePicker: type a date and press Enter to commit it, Escape closes the popup, Tab moves on (and between the two inputs of a range). The input stays the single keyboard target; the calendar cells are never focused.

On top of antd, the month, quarter, year and decade panels take arrow keys, PageUp/PageDown, Home/End and Enter while the popup is open (see the demo above); the highlighted tile is outlined and the page follows it. On those panels the arrow keys therefore no longer move the text caret while the popup is open. The date and week panels keep antd's behaviour: no arrow-key navigation, arrow keys move the caret.

### Migrating from the previous lobe DatePicker

- `Date` values → `Dayjs`: wrap with `dayjs(date)` when passing a value and call `.toDate()` in `onChange`. `onChange` now also receives the formatted string.
- `mode="month"` / `mode="year"` → `picker="month"` / `picker="year"`. `mode` now means the controlled panel, as in antd.
- `min` / `max` → `minDate` / `maxDate` (`Dayjs`); `disabledDate(date: Date)` → `disabledDate(current: Dayjs, info)`.
- `DateRangePicker` clears to `null` instead of `[null, null]`.
- The trigger is now an `<input>` instead of a `<button>`; the panel no longer moves focus into the day grid.
