`@lobehub/ui` 6 drops Ant Design. There is no `antd`, `antd-style`, `@ant-design/*` or `rc-*` dependency anymore, no `ThemeProvider`, and one component set: the base-ui components that used to live under `@lobehub/ui/base-ui` are now the root export. Component styles are compiled with StyleX into `@lobehub/ui/style.css`, and the theme is a static stylesheet switched by `data-*` attributes.

Requirements: React 19, `motion` 13 or 14, `@lobehub/icons` 6 and `@lobehub/fluent-emoji` 5 (both on the `beta` tag during the beta).

## Upgrade steps

1. Update the dependencies and remove antd:

   ```bash
   pnpm add @lobehub/ui@^6.0.1 @lobehub/icons@beta @lobehub/fluent-emoji@beta motion@^14 --registry=https://registry.npmjs.org
   pnpm remove antd antd-style     # plus any @ant-design/* packages you have
   pnpm list @lobehub/ui --depth 0 # check the resolved version; use pnpm -r list in a workspace
   ```

2. Run the codemod from the repository root. `.` also covers build config (Vite aliases, test mocks); `node_modules`, `dist`, `es`, `build` and `.next` are skipped. Run it without `--dry` once the diff looks right, then run your formatter:

   ```bash
   npx --registry=https://registry.npmjs.org @lobehub/ui-codemod@latest v6 . --dry
   npx --registry=https://registry.npmjs.org @lobehub/ui-codemod@latest v6 .
   ```

   It rewrites `@lobehub/ui/base-ui` imports, moves the `antd-style` helpers to `@lobehub/ui`, renames the `Theme` type, and lists everything else it found with a file, a line and a link into this page.

   Each run saves Markdown and JSON reports in a fresh `.lobe-ui-codemod/v6-*/` directory and prints their absolute paths with a short summary and the next action. Dry-runs also save a patch; review it before running without `--dry`. `--report migration.md` chooses a custom path with matching JSON / patch files; existing outputs are preserved, so use a new path on rerun. `--json` keeps stdout machine-readable and still saves the reports.

   Coding agents should read the JSON `summary` and `nextAction`, then work through `tasks`. Tasks merge repeated hints while retaining every location and a stable ID; `manual-fix` and `review` distinguish reported issues from checks. The JSON includes `schemaVersion`, `codemodVersion`, `mode`, scan scope and artifact paths. Raw `items` remain available for compatibility. Locations refer to the transformed source even during preview. Exit code 0 means no parse errors; the reports still require verification.

   CSS / Less / Sass files are scanned for `.ant-*` selectors and `--ant-*` variables without rewriting them. Known matches include specific slot / token hints; unknown matches require a manual choice. Only the selected paths and supported file types are scanned. Search Vue / Svelte / MDX, dynamically built selectors and any ignored sources the app consumes separately. Reports always include **Next steps**, including when there are no static findings; JSON exposes the same checklist as `nextSteps`.

3. Work through the report. Each rule matches a section below. A coding agent can do this with the `lobe-ui-v6-migration` skill:

   ```bash
   npx skills add lobehub/lobe-ui
   ```

4. Complete [test migration](#test-migration), then [verification](#verification). If installation or startup fails, check [installation troubleshooting](#installation-troubleshooting) first.

## Theming

`ThemeProvider` is gone. Theme tokens are CSS variables (`--lobe-*`) shipped in a stylesheet, and the appearance and colors are attributes on `<html>` or on any subtree.

| File | Content | Required |
| --- | --- | --- |
| `@lobehub/ui/theme.css` | token variables for every appearance, primary and neutral color, plus essential rules | yes |
| `@lobehub/ui/style.css` | compiled component styles | yes |
| `@lobehub/ui/global.css` | document resets (body font and background, scrollbars, antd's old `reset.css`) | optional |

Before:

```tsx | pure
import { ThemeProvider } from '@lobehub/ui';

export default ({ children }) => (
  <ThemeProvider
    appearance={appearance}
    customTheme={{ neutralColor: 'mauve', primaryColor: 'blue' }}
    enableGlobalStyle
  >
    {children}
  </ThemeProvider>
);
```

After:

```tsx | pure
import '@lobehub/ui/theme.css';
import '@lobehub/ui/style.css';
import '@lobehub/ui/global.css';

import { ConfigProvider, setLobeTheme } from '@lobehub/ui';
import { motion } from 'motion/react';

// client only: touches document; on the server render <LobeThemeScript /> in <head>
setLobeTheme({ appearance: 'dark', neutralColor: 'mauve', primaryColor: 'blue' });

export default ({ children }) => <ConfigProvider motion={motion}>{children}</ConfigProvider>;
```

- `setLobeTheme({ appearance, primaryColor, neutralColor }, root?)` writes `data-theme`, `data-primary-color` and `data-neutral-color` on `<html>` (or `root`). Call it whenever the user changes the theme.
- `<LobeThemeScript appearance="system" />` renders an inline script for the document `<head>` that sets the attributes before the first paint, so server-rendered pages do not flash. It does not persist anything; keep the user's choice in your own storage or in `next-themes`.
- With `next-themes`, let it own `data-theme` (`attribute="data-theme"`) and only pass `primaryColor` / `neutralColor` to `setLobeTheme` or `LobeThemeScript`.
- `<ThemeScope appearance="dark">` renders a `div` with its own attributes, for an island with a different theme. Unset props inherit from the parent scope.
- `useThemeMode()` returns `{ appearance, isDarkMode }`; `useTheme()` returns the token values plus `appearance` and `isDarkMode`, for code that needs concrete values (canvas, charts). Both read the nearest `ThemeScope`, else `<html>`.

`ConfigProvider` takes over what `ThemeProvider` did besides theming: web fonts (`customFonts`, `enableCustomFonts`), the portal host for popups (`#lobe-ui-theme-app`, exported as `LOBE_THEME_APP_ID`), and `direction`. These `ThemeProvider` props have no successor: `customTheme` (use the attributes), `customToken`, `customStylish`, `theme` (antd), `themeMode`, `enableGlobalStyle` (import `global.css`) and `appId` (the portal host id is fixed to `lobe-ui-theme-app`).

`ThemeProvider` also rendered antd's `App` and `ConfigProvider`. If your app used `App.useApp()` for `message` / `modal` / `notification`, switch to `toast` and `createModal` from `@lobehub/ui`.

## Styling API

`antd-style` is not used anymore. `@lobehub/ui` exports the same helpers on its own emotion instance (cache key `acss`), so the codemod only changes the import source:

| antd-style | @lobehub/ui | Notes |
| --- | --- | --- |
| `createStaticStyles(({ css, cx, cssVar, responsive }) => …)` | same |  |
| `cssVar` | same | resolves to `var(--lobe-*)` instead of `var(--ant-*)` |
| `cx`, `css`, `keyframes`, `injectGlobal` | same |  |
| `responsive`, `useResponsive` | same | keys `xs`–`xxl`, `mobile`, `tablet`, `laptop`, `desktop` |
| `useTheme` | same | tokens + `appearance` + `isDarkMode`; no `stylish` or `prefixCls` |
| `useThemeMode` | same | `{ appearance, isDarkMode }`; no `themeMode` or `setThemeMode` |
| `createGlobalStyle` | same | function interpolations receive `{ theme }` (a `LobeTheme`) |
| `extractStaticStyle` | same name | returns `{ css, ids, key, tag }[]` (`tag` is a `<style>` HTML string); there is no React `style` element, and the antd cache options are ignored |
| `Theme`, `ThemeAppearance` types | `LobeTheme`, `LobeAppearance` |  |
| `StyleProvider` | — | it only passed the antd SSR cache; delete it and keep its children |
| `createStyles`, `createStylish`, `useAntdToken`, `ThemeProvider` | — | rewrite with `createStaticStyles` + `cssVar` |

`setThemeMode` callers switch to `setLobeTheme({ appearance })` or their `next-themes` setter. Keep an "auto" choice in your own state; `appearance` is always the resolved `'light'` or `'dark'`.

## CSS cascade

Every rule Lobe UI ships sits in the `lobe-base`, `lobe-popup` and `lobe-ui` cascade layers, so unlayered CSS always wins over it. That changes two things:

- Your unlayered global resets (`* { margin: 0 }`, `button { … }`, normalize.css) now beat component styles. Move them into a layer declared before Lobe UI's. This statement must be the first CSS the app loads, before `theme.css` and `style.css`:

  ```css
  @layer reset, lobe-base, lobe-popup, lobe-ui;

  @layer reset {
    button {
      font: inherit;
    }
  }
  ```

  With Tailwind v4, use `@layer theme, base, lobe-base, lobe-popup, lobe-ui, components, utilities;` as the first CSS, before `@import 'tailwindcss'`.

- Overrides no longer need specificity tricks, but they must target what components expose: `className`, `style`, the `classNames` / `styles` slot props, and documented `data-*` attributes. Generated class names (StyleX hashes) change between releases.

## Table and ProTable

`Table` renders its own DOM on TanStack Table instead of `@rc-component/table`; the antd-shaped API (`columns`, `rowSelection`, `expandable`, `onChange`, `scroll`, `sticky`, `summary`, `virtual`, the ref) is unchanged. The stateless parts are exported as atoms (`TableRoot`, `TableRow`, `TableCell`, …) for custom tables. Deprecated aliases are removed; the codemod reports each one (R11):

| v5 | v6 |
| --- | --- |
| `bordered` | `variant="outlined"` |
| `expandedRowRender`, `expandIcon`, `indentSize`, `childrenColumnName`, `expandIconColumnIndex` | the same keys under `expandable` |
| `classNames` / `styles` keys `cell`, `row`, `wrapper`, string `header` / `body` | `body.cell`, `body.row`, `section`, `header.cell`, `body.wrapper` |
| `emptyText` | `locale.emptyText` |
| `size="medium"` (Table and ProTable `size` / `defaultSize`) | `size="middle"` |
| `pagination.position` | `pagination.placement` (`topStart` … `bottomEnd`) |
| `locale.filterCheckall` | `locale.filterCheckAll` |
| `expandable.expandedRowOffset` | `Table.EXPAND_COLUMN` in `columns`, with the columns before it `fixed` |
| `measureRowRender` | removed; the table measures its columns itself |
| `components.body` as a render function | removed; use `virtual` |
| ProTable `ghost` | removed; ProTable has no card |

`ProTable` moved to its own entry, `@lobehub/ui/pro-table` (the codemod rewrites the import), so apps that only use `Table` don't load the form layer.

## DatePicker

`DatePicker` is the v5.64 base-ui picker on a fork of `@rc-component/picker` 1.12.2 (the core antd's DatePicker uses), kept inside `@lobehub/ui` with its popup on Popover and Motion, with antd's API (`picker`, `mode`, `showTime`, `presets`, `multiple`, `needConfirm`, `cellRender`, Semantic DOM, `generatePicker`). `DatePicker` / `DateRangePicker` keep native `Date` values (inputs also accept `Dayjs`, strings and timestamps); code written for antd's `Dayjs` DatePicker moves to `DayjsDatePicker` / `DayjsDateRangePicker`. Code written for v5's `DatePicker` keeps working, except for the aliases v5.64 still accepted; the codemod reports each one (R12):

| v5 | v6 |
| --- | --- |
| `min` / `max` | `minDate` / `maxDate` |
| `footer` | `renderExtraFooter={() => footer}` |
| `bordered={false}` | `variant="borderless"` |
| `onSelect(date)` | `onCalendarChange(date, dateString, info)` |
| `size="middle"` | `size="medium"` |
| `popupAlign` / `builtinPlacements` | `placement` (flips vertically, shifts to stay on screen) |
| `transitionName` | none; the popup animates with Motion, style it through `classNames.popup.root` |

`DateRangePicker` and `DatePicker.RangePicker` are the same component; both names stay. `@lobehub/ui` depends on no `@rc-component/*` package; take `PickerRef` / `GenerateConfig` types from `@lobehub/ui`. R6 reports `@rc-component/picker` imports: a date-fns, moment or Luxon config from `@rc-component/picker/generate/*` still works with `generatePicker` once you install that package yourself. The popup root carries Base UI's `data-side` / `data-open` attributes instead of the `-dropdown-hidden` / `-dropdown-placement-*` classes.

If you used the hand-written picker from the v6 betas, values stay native `Date`; use `picker="month"` / `picker="year"` where you passed `mode` (R12 flags literal `mode="month"` / `mode="year"`). If you moved to `Dayjs` on beta.8, switch those call sites to `DayjsDatePicker` / `DayjsDateRangePicker` or back to `Date`.

## Behavior changes

- **Form values are the whole store.** `getValues()`, `onSubmit(values)` and the second argument of `onValuesChange` from `@lobehub/ui/form` return every value in the store (initial values, `setValues` and edits), not only the mounted fields as antd's `getFieldsValue` / `onFinish` did. Pick the fields you submit explicitly; never pass a database row as `initialValues` and post `getValues()` back.
- **Menu items are a union type.** `DropdownItem` is a union, so an inline `onClick({ domEvent })` loses its contextual type. Annotate the argument as `MenuInfo`.
- **Menus open on click.** `DropdownMenu` defaults to `trigger="click"` (antd `Dropdown` opened on hover) and has no menu-level `onClick`; move a `switch (key)` from `menu.onClick` into each item's `onClick`.
- **No arrows by default.** `Tooltip` and `Popover` render without an arrow unless you pass `arrow`.
- **Popup containers.** There is no `.ant-app` element. Code that looked it up (`getPopupContainer`, portals) uses `document.getElementById(LOBE_THEME_APP_ID)`.
- **`Video` ref is a player.** `ref` on `Video` now receives a `VideoPlayer` (`play`, `seek`, `getState`, …) instead of the wrapper `<div>`; the element is `player.root`, the `<video>` is `player.video`.
- **antd class names and variables.** `.ant-*` selectors and `--ant-*` variables match nothing. Use component props for overrides and `cssVar` / `--lobe-*` for tokens.
- **Dependencies no longer installed.** `@lobehub/ui` stopped depending on `ahooks`, `swr`, `polished`, `immer`, `use-merge-value`, `react-merge-refs`, `fast-deep-equal`, `numeral`, `url-join`, `ts-md5`, `uuid`, `marked`, `query-string`, `class-variance-authority`, `react-rnd`, `react-zoom-pan-pinch` and `@floating-ui/react`, among others. An app that imported any of them without declaring it now has to add it to its own `package.json`.
- **Spline runtime is an optional peer.** `Spline` (`@lobehub/ui/awesome`), `LogoThree` and `LogoSpline` (`@lobehub/ui/brand`) load `@splinetool/runtime` only when they render, and `@lobehub/ui` no longer installs it. Apps that render them add it themselves: `pnpm add @splinetool/runtime`.
- **`CodeDiff` options type.** `diffOptions` follows `@pierre/diffs` 1.5, whose `FileDiffOptions` takes a second type argument: annotate it as `FileDiffOptions<string, undefined>`.
- **Resets.** antd's `reset.css` (box-sizing, margins, list styles) is now part of `global.css`. Apps that relied on it without importing antd's stylesheet need `global.css`.

## Test migration

Save the relevant test results before upgrading, using the same environment and commands. After migration, compare failures against that baseline; record old failures separately from new regressions.

Tests that render `Button`, `Drawer` or other motion consumers need the same motion context as the app. A local React Testing Library wrapper is enough:

```tsx | pure
import { render } from '@testing-library/react';
import { MotionProvider } from '@lobehub/ui';
import { motion } from 'motion/react';
import type { ReactNode } from 'react';

const Wrapper = ({ children }: { children: ReactNode }) => (
  <MotionProvider motion={motion}>{children}</MotionProvider>
);

export const renderWithUI = (ui: ReactNode) => render(ui, { wrapper: Wrapper });
```

Use your app's `ConfigProvider motion={motion}` instead when the test also relies on locale, direction or popup containers. This example is a local test helper, not a new package export.

Whole-package mocks often lose exports needed by real components. Preserve the actual module and override only the member under test:

```ts | pure
vi.mock('@lobehub/ui', async (importOriginal) => {
  const actual = await importOriginal<typeof import('@lobehub/ui')>();
  return { ...actual, toast: vi.fn() };
});
```

For Jest, use `jest.requireActual` where supported, or the project's ESM mocking setup. Keep `createStaticStyles`, `Text` and other consumed exports available. R13 flags mocks without a recognizable actual-module import; inspect custom mock helpers manually.

`InputNumber` renders a visible text input plus a hidden form input. Query the visible control with `screen.getByRole('textbox')` (scope with `within` when necessary), then assert its value or exercise `onChange`. Avoid `querySelector('input')`, `querySelectorAll('input')[0]` and old DOM snapshots. Check accessible names independently: v6.0.1's `Switch` convenience component does not forward `aria-*`; use a visible label linked with `htmlFor` / `id` and verify it by role and name.

## Verification

Work through each report item and parse error, including informational items and prop spreads. The codemod cannot infer callback semantics, dynamically assembled props, preprocessor expansion or the meaning of an app's custom palette. A report with no findings still requires these checks:

- Run type-check, lint and the relevant tests; compare with the pre-upgrade baseline.
- Compare key pages in light and dark mode on desktop and mobile. Inspect dividers, container backgrounds and app-owned neutral scales; swapping a variable prefix alone does not preserve the intended appearance.
- Open and close a popup / drawer, submit a form, check focus and accessible names, and exercise changed callbacks such as `Tag.onClose`, `Drawer.onClose` and Select values.
- Use the documented `classNames` / `styles` slots for [Segmented](/components/segmented#custom-semantic-dom-styling) and [DatePicker / RangePicker](/components/date-picker#custom-semantic-dom-styling). RangePicker's `styles.input` targets both inputs; `styles.root` controls the overall width.
- Re-run the codemod to check mechanical leftovers. Delete temporary overrides or library patches only after their replacements pass the relevant checks.

## Installation troubleshooting

- **New release returns 404:** check that the exact version is available from `https://registry.npmjs.org`; check any scope-specific registry override in the project. A mirror may not have synchronized yet. After installing, verify the resolved version with `pnpm list @lobehub/ui --depth 0`, or `pnpm -r list @lobehub/ui --depth 0` for consuming workspaces. Record the resolved codemod version when reproducing a report.
- **pnpm blocks a fresh version:** inspect `minimumReleaseAge`. Wait for the configured age or use the project's package-scoped exception for the required package; avoid globally disabling the safeguard.
- **Vite white screen after upgrading:** stop the old server and restart Vite with `--force` to rebuild dependency optimization. Recheck the browser console and resolved versions before attributing the failure to component code.

## Known issues

- Use `@lobehub/ui@6.0.0-beta.2` or later: `6.0.0-beta.1` declared `@lobehub/icons@^5` and `@lobehub/fluent-emoji@^4` as peers.
- Use **6.0.1 or later** for custom neutral hex / registered scales and the library's React 19 `element.ref` warning fix. After checking light/dark colors and child refs, remove only the temporary CSS injection, library patch or warning suppression that compensated for these issues.
- In 6.0.1, `Switch` does not forward `aria-*` through its convenience component, and `InputPassword` uses fixed English visibility-toggle labels. For Switch, use a visible label linked with `htmlFor` / `id`; for localized password toggles, use `visibilityToggle={false}` and an accessible custom `suffix`. Check the installed version before removing these workarounds.
